# server

Generated by `prisma orm init` with the Minimal template.

## First run

1. Set `DATABASE_URL`, `JWT_SECRET` (at least 32 random characters), `BOOTSTRAP_ADMIN_EMAIL`, and `BOOTSTRAP_ADMIN_PASSWORD` in `.env`. The bootstrap password should be at least 12 characters.
2. `npm run dev` — starts the API. On the first login it creates the portal tables and the executive bootstrap account. Evidence PDFs are stored under `uploads/evidence` unless `ESG_UPLOAD_DIR` is set.
3. Sign in with the bootstrap email and password. Use **Manage users** to add engineers, HSE officers, subsidiary heads, and auditors. Assign engineers/HSE officers to sites and subsidiary heads to subsidiaries.

Measurements are site scoped, require a PDF proof, are normalized before storage, and are deduplicated by site/month/metric. Subsidiary heads can approve or reject entries in their assigned scope. Executives get totals calculated from site records; auditors have global read-only access. Login uses a signed bearer token, and the API checks role and site scope on each protected route.

The API creates its ESG tables on first use. It does not insert sample site records.

## Available scripts

- `npm run dev` — run the Prisma ORM sample script

### Database and migrations

- `npm run contract:emit` — emit contract artifacts after contract changes
- `npm run db:init` — initialize database state manually
- `npm run db:update` — update database state manually
- `npm run migration:plan` — create a migration plan
- `npm run migrate` — apply a planned migration
- `npm run db:seed` — insert sample users manually (run after `db:init`)

## Prisma ORM

Prisma ORM setup is scaffolded in:

- `prisma/schema.prisma`
- `prisma.config.ts`
- `prisma/db.ts`
- `src/lib/prisma.ts`

For provider-specific Prisma ORM reference docs, see `prisma-8.md`. Prisma ORM skills live in the upstream `skills/` directory: https://github.com/prisma/prisma/tree/main/skills.

Node-based Prisma ORM projects expect Node.js 24 LTS or newer.
