# server

Generated by `prisma orm init` with the Minimal template.

## First run

1. Set `DATABASE_URL`, `JWT_SECRET` (at least 32 random characters), `BOOTSTRAP_ADMIN_EMAIL`, and `BOOTSTRAP_ADMIN_PASSWORD` in `.env`. The bootstrap password should be at least 12 characters.
2. `npm run dev` — starts the API. It creates the portal tables and executive bootstrap account on first auth request. Evidence PDFs are stored under `uploads/evidence` unless `ESG_UPLOAD_DIR` is set.
3. Sign in as **CSO / Executive** with the bootstrap email and password. CSO login checks the credentials against these environment values. Add sites before inviting staff.
4. Site Engineers can request access from the sign-in screen. They choose a site and wait for a Subsidiary Head with access to that site to approve. Approved accounts and their site scopes are saved in the database. Pending requests appear in the reviewer’s top-bar notification menu.
5. Use **Manage users** to create Subsidiary Head and Independent Auditor accounts. Assign subsidiary heads to subsidiaries; auditors receive read-only organization-wide access.

Measurements are site scoped, require a PDF proof, are normalized before storage, and are deduplicated by site/month/metric. Subsidiary heads can approve or reject engineer entries in their assigned scope. The CSO / Super Admin gets totals calculated from site records; independent auditors have global read-only access. Login uses a signed bearer token, and the API checks role and site scope on each protected route.

The API creates its ESG and access request tables on first use. It does not insert sample site records.

## Available scripts

- `npm run dev` — run the Prisma ORM sample script

### Database and migrations

- `npm run contract:emit` — emit contract artifacts after contract changes
- `npm run db:init` — initialize database state manually
- `npm run db:update` — update database state manually
- `npm run migration:plan` — create a migration plan
- `npm run migrate` — apply a planned migration
- `npm run db:seed` — insert sample users manually (run after `db:init`)
